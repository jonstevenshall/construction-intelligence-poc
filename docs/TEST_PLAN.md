# Test plan

Run `python3 -m unittest discover -s tests -v` and `node --check web/app.js`.

Automated checks cover exact corpus scale/month coverage, quote and option arithmetic, GST display differences, deposits on the declared basis, included-elsewhere and rate-only semantics, source SHA-256 and line references, material scenario coverage, calendar boundaries, separation of public snapshots from synthetic fixture truth, rainfall coverage and recovery-day union, missing-weather abstention, as-of cutoffs, diesel GST conversion, source references and idempotent public-data indexing, graph/line counts, retrieval/date restrictions, no future evidence in estimates, estimate bounds and invalid inputs, question ordering and range reduction, evaluator false negatives, concurrent/persistent spend caps, expensive-model rejection and zero network calls when disabled.

Browser checks: fresh Calculation and Context contain no preset project values, scenario forms or source catalogue; Bids contains no automatic first-job cards. A conversational calculation populates quantities, formulas and the cost breakdown. Subsequent evidence retrieval adds new local findings and actual source links without a fixed topic list, and only retrieved quote IDs appear in Bids. Selecting a reference job explicitly loads that job's stored quotations. Refresh opens empty panels and offers Resume previous simulation; resuming restores all panels together. New project clears all three panels, including in-flight source-card loads. A vague brief can receive a direct response without a calculator call; conceptual replies retain the current estimate. Unknown locations receive no substituted map data. Source links open real stored records and the API key never enters the browser.

Conversation recovery checks: earlier bid citations survive twelve turns; imported citations survive a follow-up and remain excluded before availability; new narrative facts do not invalidate an already calculated package. A received truncated response is charged and permits exactly one tool-free explanation repair. Failed repair cannot display fabricated citations or attach a calculated package to altered pricing inputs. A prior estimate is retained but explicitly marked not updated. Provider rate-limit errors are not treated as malformed answers and are not automatically retried.

Data checks: actual schemas/counts; CSV leading-zero preservation and JSON native types; data dictionary available through the generic agent tool; preview without writes; edit invalidates review; exact P/V/Q links and namespaced external entities; immutable/idempotent versions; atomic rollback of records, links, index and original file on indexing failure; post-import retrieval, source/hash inspection and graph traversal on SQLite and PostgreSQL. Browser import tests use a disposable database and invented evidence, with no live model call.

Live-model acceptance still requires an authenticated deployed run. Try a school administrator with only rough dimensions and an intended use, answer “I don't know” to a technical detail, change the soil-disposal assumption, ask a tangent and refer back to an earlier source over at least ten turns. Expect an early scenario range, one simple useful question, labelled assumptions instead of mandatory lot numbers/surveys, no request for unavailable photo uploads, and no silent property clearance. Prompt guidance is not proven by scripted provider fixtures.

PostgreSQL checks: start an isolated pgvector service, ingest into `earthworks_lab`, verify 300 projects/50 vendors/1,000 quotes/21,000 lines/7,000 chunks/45,000 edges, verify filtered vector retrieval and graph traversal, then run the same application against that service.

Synthetic tests establish internal consistency and implementation behaviour only. They do not establish forecast accuracy, neural retrieval quality, real-world value of question ordering, construction-domain correctness or performance of any external product. Those need representative held-out real cases and practitioner review.

Authentication regression: missing or invalid demo credentials must show the unlock screen with the workspace inaccessible. Only accepted credentials unlock chat. A failed send must remove optimistic bubbles, preserve the draft and keep an inline error visible. Offline/misconfigured model status disables Send; the API key never enters the browser.
